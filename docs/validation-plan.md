# spinloop 实验验证方案

项目仓库：[ruyishu/spinloop](https://github.com/ruyishu/spinloop) ｜ 2026-11-18 ｜ 实验设计，尚无结果

## 1. 一句话假设与推进顺序

冻结原版 Qwen3。第 1 圈走原模型，第 2 圈让各层输入转一个学到的角度，第 3 圈转两倍，第 4 圈转三倍。每圈都读取上一圈的隐藏状态，最后一圈才用于决定下一个 token。研究问题是：在训练参数和推理计算可比时，这条随圈数变化的旋转规则，能否让模型从额外的深度中获益？

| 优先级 | 要判断的事 | 足够回答的实验 |
|---|---|---|
| 第一批，值得现在做 | 第二圈能否用少量旋转参数，从上一圈的信息里获益？ | 0.6B、两圈、2,048 道训练题。和原模型、无旋转两圈、单圈 SFT、同参数两圈 LoRA 比较。 |
| 第二批，两圈有信号再做 | 圈数本身是否值得编码进旋转？ | 同一训练协议下比较“后几圈一直用 R”和“后几圈用 R、R²、R³”。从第 3 圈起，两者才有区别。 |
| 第三批，有机制证据再做 | 结果能否在另一个模型规模、另一类题目、训练深度之外复现？ | 1.7B 复现；跨题集评测；用新生成的多跳查表任务诊断；最多训练 4 圈，盲测 6、8 圈。 |

论文主张按证据递进。单圈复现原模型是设计性质；两圈变好是循环适配证据；按圈旋转优于固定旋转才支持核心机制；训练外圈数继续提高是独立的加分项。训练统一采用有标签 SFT，数据直接用人工解答或程序真值，无需教师模型。

## 2. 预先固定模型结构

**主干。** 首轮用官方聊天版 `Qwen/Qwen3-0.6B`，确认后用 `Qwen/Qwen3-1.7B`。整套 28 个 decoder block 重复使用，每圈保留原来的层序、因果注意力、token 位置和 token RoPE。词嵌入、28 层、全部 norm 和输出头都冻结。两种规模各固定模型 revision、tokenizer 和模板。模型规格见 [0.6B 配置](https://huggingface.co/Qwen/Qwen3-0.6B/blob/main/config.json) 和 [1.7B 配置](https://huggingface.co/Qwen/Qwen3-1.7B/blob/main/config.json)。

**每圈怎么转。** 第一版只在每层的 `q_proj` 和 `v_proj` 的线性投影前旋转，两个投影各自学一套。按连续 16 个输入维度分一块，各块独立。每块只存反对称矩阵 A 的 120 个独立参数。用 Cayley 变换求一个正交矩阵 R，再把第 k 圈的投影写成：

$$R=(I-A)^{-1}(I+A),\qquad y_k=W R^{k-1}x.$$

第 1 圈直接调用原始投影，第 2、3、4 圈依次用 R、R²、R³。这里“角度翻倍”指每个不变旋转平面中的角度翻倍。直接把 A 乘以圈数再做 Cayley，一般得不到同样的结果。A 零初始化；用 FP32 小块线性方程求解，避免构造完整的隐藏维方阵，旋转结果再参与主干的混合精度计算。后几圈共用同一套 A。

**每圈吃什么。** 设 e 是原始 token embedding，hₖ 是该位置第 k 圈最后一层输出、最终 RMSNorm 之前的 residual。第一圈输入 e。后续圈默认采用不含可训练参数的回接，逐 token 计算：

$$x_{k+1}=e+\alpha\,\frac{\mathrm{RMS}(e)}{\mathrm{RMS}(h_k)+\epsilon}h_k,\qquad \alpha=1.$$

这保留了词本身，并让上一圈的状态和词向量有相近量级。它是待验证的工程选择。所有自建循环对照用同一个回接、同一组投影、同一因果掩码。各圈都可以通过冻结的最终 RMSNorm 和原始 LM head 读出预测。固定 K 的正式生成始终用第 K 圈选下一个 token。

**为什么选 16 维块。** 该设计允许与 LoRA 精确配平，排除“谁的参数更多”的争议。只统计真正可训练的独立标量，不采用填充参数或训练完整反对称块再把冗余元素也计入预算。

| 模型 | 每层 Q/V 各自输入维度 | Spin 可训练参数 | 相同参数预算的 Q/V LoRA |
|---|---:|---:|---|
| Qwen3-0.6B | 1,024 | 430,080 | Q rank 3、V rank 3，共 430,080 |
| Qwen3-1.7B | 2,048 | 860,160 | Q rank 3、V rank 6，共 860,160 |

Spin 总数 = 28 层 × 2 个投影 × (输入维度 / 16) × 120。LoRA 总数按每个投影的 rank × (输入维度 + 输出维度) 求和。两款模型的 Q 输出均为 2,048，V 输出均为 1,024。用共享 LoRA 做多圈对照时，跨圈复用同一套 LoRA 参数。低秩分支采用非退化的常规初始化，首圈绕开循环适配器，单圈 SFT 对照除外。

## 3. 最小可行实验：两圈到底值不值得走下去

### 数据、训练和评分

- 从官方 GSM8K 的 train 固定抽 2,048 题训练，另留互不重叠的 512 题开发集。先固定去重方法、划分种子和样本 ID，以后扩到剩余 train 时仍保留这 512 题。官方 test 留到配置锁定后使用。[GSM8K](https://huggingface.co/datasets/openai/gsm8k)
- 使用原题及人工解答。统一模板要求简短列式并在末行写 `#### 数字`，训练和推理都关闭 Qwen3 thinking 模式，不生成隐藏思维标签。只在 assistant 解答和结束符上计算常规 next-token 交叉熵。短推理 SFT 的能力结论限于这个解码设置。[Qwen3 模型卡](https://huggingface.co/Qwen/Qwen3-0.6B)
- 建议起点为 1 epoch、有效 batch 16（共 128 次更新）、训练长度 1,024、BF16、AdamW、warmup 5%、梯度裁剪 1.0。学习率先给 Spin 和 LoRA 各同样的两次机会，例如 3e-4、1e-3；用独立训练内校准子集或预留的开发集选择，记录所有试验。首轮排查可各先用 3e-4 一次。过滤超长训练样本时保留完整答案并让所有组使用同一清单。原模型与无旋转循环不训练。
- 推理用相同的零样本模板、greedy、每题最多 256 个新 token、相同停止条件。主指标是题级数值 exact match。统一处理千分位、符号、等价小数；缺少可解析答案或截断且无最终答案按错。另报正确格式率、截断率和输出长度，以识别格式改善。可用宽松抽取器复核一次，规则先在开发集冻结。
- 首圈冻结且未注入适配，可在确认等价后无梯度运行。后续有训练参数的圈保留反向传播链，四圈训练时不随意 detach。先采实际吞吐、显存、长度，再定 GPU 小时；首轮两个 0.6B 配置可分到两张 L20 各跑一个，显存不足时先缩 microbatch 并累积梯度。

### 首轮五组

| 组别 | 圈数 | 训练什么 | 它回答的问题 |
|---|---:|---|---|
| A 原版 Qwen3 | 1 | 无 | 额外计算是否超过原模型起点？ |
| B 无旋转循环 | 2 | 无，同一回接 | 单纯多过一遍主干会怎样？ |
| C 单圈 Spin-SFT | 1 | 在唯一的一圈启用 R，训练同样的 430,080 个参数 | 直接用相同数据做普通旋转微调能做到什么程度？ |
| D 两圈 LoRA | 2 | 只在第 2 圈启用，精确配平参数 | 同一循环和训练预算下，常规适配器有多强？ |
| E 两圈 SpinLoop | 2 | 只在第 2 圈启用 R | 冻结主干后旋转能否用好第二圈？ |

A/B 是零训练参照。D/E 才是首轮的训练和深度配平比较。C/E 配平数据和可训练参数，另记两者算力差距。A 直接复用所有首圈等价组的基线。无需在这个阶段训练 6 圈或复现完整 TaH2。

### 最先做的正确性验收

1. **首圈等价。** 先在至少 32 个长短不一的固定输入上，逐有效位置对照原始模型 logits，再测固定条件下的贪心生成。相同权重、dtype、kernel、缓存策略时优先要求逐元素一致；因内核差别只能近似相等时，记录最大误差和 token 差异，定位后再决定能主张何种等价。训练后重测，主干哈希应一致。比较时给两边相同的 token 前缀。
2. **零旋转等价。** A 参数全零时，两圈 Spin 与无旋转两圈应一致。训练几步后旋转参数应有有限非零梯度，冻结权重不变。另用小块验证 RᵀR≈I 和第 3 圈实际用 R²。
3. **无未来信息和缓存串圈。** 改写输入后半段，之前各位置的输出应保持一致。无缓存全前缀实现作为参照，逐 token 增量解码需对齐。每个（圈、物理层）有逻辑独立的 KV 缓存；同一 token 的位置编号在重新进圈时不增加。正式评估前对 K=1、2、4 各测一次。
4. **训练确实连通。** 用 16–32 个示例试拟合，比较正确答案损失和梯度趋势。若连训练样本都无变化，先查标签掩码、梯度、回接尺度、旋转注入位置。这个步骤只验工程，不充当能力证据。

### 怎么读结果

每道开发题保留 A 至 E 的最终答案、是否正确、截断标志和生成长度。对同一题比较 A 与 E，数“原先错、现在对”和“原先对、现在错”。净提升（百分点）= 100 ×（救回题数 − 改错题数）/ 总题数。D/E、C/E 也做逐题配对。它们是完整生成的比较；若想知道同一 token 是否被改好，另外在相同标准前缀下比较 token top-1 和正确 token 的 NLL。

下列是事先可调整的工程投资门槛，建议在看开发结果前定稿：

| 开发集结果 | 下一步 |
|---|---|
| E 比 A、B 均高，且比 A 至少约 +2 个百分点；和 D 的差距不超过约 2 个百分点，或优于 D | 四圈机制实验值得开。512 题的 +2 个百分点约等于净增 10 题，只作筛选信号。 |
| E 赢 A/B，但明显落后 C | 普通 SFT 的解释仍然很强。增加“去掉回接”对照再决定要不要加深。 |
| E、D 都明显落后 A 或 C | 优先检查回接与解码。工程验收通过后，两组一并对比 α=0.25 和 1，仅给一次修订机会。 |
| D 明显改善，E 仍失败 | 回接有希望，当前旋转自由度/位置可能受限。只补一次扩大块或增加投影的成对对照，重新配平 LoRA；仍无收益就暂停此版本。 |
| E 和对照差距很小，方向不稳定 | 用第二、第三个训练种子，或扩大预留验证集；低精度差异记为不确定，不因小幅正号启动 1.7B。 |

## 4. 核心机制实验：按圈继续转是否真的有价值

只在 0.6B 首轮有信号后启动。将 GSM8K 官方训练划分中除固定开发集外的数据用于训练；建议从 1 epoch 开始。每个训练 batch 在 K=2、3、4 中等概率选取一个深度，只对末圈输出算同样的 SFT 损失。各组共用预生成的样本顺序、深度序列和监督 token 总数。所有卷入比较的模型都按自己的方案从同一起点独立训练。测试同一 checkpoint 的 K=1、2、3、4 表现。

| 方法 | 第 1–4 圈适配 | 回答的问题 |
|---|---|---|
| 恒定旋转 | I，R，R，R | 这是最重要的对照。参数数目、回接、训练数据、深度均相同，只去掉角度随圈数增长。 |
| SpinLoop | I，R，R²，R³ | 主方法。优先看 K=4 对恒定旋转的题级准确率差。 |
| 按圈缩放的共享 LoRA | W，W+Δ，W+2Δ，W+3Δ | 给同样少的参数、同样的圈数信号。若也能做到，说明简单地让适配量随深度增长就有价值。 |
| 单圈 Spin-SFT | 同一圈应用 R | 在完整训练集上复跑，估计普通任务微调的贡献。 |

两个针对性干预，用于解释主要结果：

- **切断回接。** 令 α=0，每圈重新读原 embedding。先在训练好的主模型上做干预，再在相同规则下训练一个 α=0 的控制模型；前者测模型是否依赖上一圈，后者防止将推理时输入分布改变误认为通信有效。匹配末圈旋转与训练深度。若独立训练的 α=0 也同样好，就缺少“上一圈真的做了有用计算”的证据。
- **深度编号消融。** 用同一 checkpoint 在 K=4 把 R²、R³ 改为 R 或交换顺序，看固定前缀 NLL 和题级表现；主要结论仍依赖独立训练的恒定旋转对照。预算允许时，可加入传统的加性圈数编码或每圈独立 LoRA；明确其新增参数和外推定义。

**确认方式。** 预定主比较为 GSM8K 官方 test 上 K=4 的 SpinLoop 对恒定旋转。开发集选定方案后用 3 个配对训练种子复跑，封存配置后统一测测试集。逐种子给差值、报告种子均值与离散程度；以题为单位成对 bootstrap 估计 95% 区间，同次抽样对所有种子用相同的题 ID，不把“3 个种子 × N 题”当作独立题目。若主差值方向稳定且区间支持正提升，再谈圈数旋转的贡献。对比 LoRA 的结果决定这一规则相对于另一种深度调制的优势；一次领先不能证明正交参数化普遍优于 LoRA。

## 5. 正式实验：外推、迁移与计算账

**训练外深度。** 训练最大 K=4，同一 checkpoint 测 K=4、6、8。预先指定 K=6 为主外推点，K=8 为压力测试。用相同题目和输出预算比较三种推理：继续乘方；到第 4 圈后固定为 R³，但仍跑满 6 或 8 圈；以及训练好的恒定旋转基线也跑同样圈数。如果 6 圈比自身 4 圈好，且比同样算了 6 圈的“封住角度”好，才支持训练外的旋转规则有增益。持平只说明可在更深处运行。完整曲线和区间都保留。

**规模与迁移。** 在 1.7B 上只复现单圈原版/单圈 SFT、SpinLoop、恒定旋转、按圈缩放 LoRA 这几条关键线。另用未经本项目训练、调参的 SVAMP 官方 1,000 题做外部算术迁移，使用同一输出规则。[SVAMP 官方挑战集](https://github.com/arkilpatel/SVAMP) 。GSM8K 与 SVAMP 都是数学文字题，结论相应限定为算术推理。

**补一个新鲜的受控任务。** 建议单独训练与评估随机多跳查表。每题随机生成 16 个标签的单环置换、打乱映射展示顺序，指定起点和要走的跳数，只输出终点标签。独立划分图、随机种子和题面变体，保证标签 token 长度一致并平衡终点。训练 1–4 跳，评测 1–4、5–8 跳，每档例如 500 题。横轴用模型圈数，纵轴用题目跳数，报告交叉表。固定跳数时增加圈数测深度外推；固定圈数、增加跳数测题目难度泛化。这个实验不预设一圈恰好等于一跳。如果要声称获得通用推理提升，再加一个独立的非算术自然语言任务。[类似的可诊断多跳任务](https://arxiv.org/abs/2610.24135)

**计算公平性。** 主表同时列精度、训练监督/处理 token、训练 GPU 小时、可训练参数、推理时平均生成 token、prefill/decode 延迟、峰值显存和吞吐。固定输入长度、生成长度、batch、硬件、精度，另做一次固定长度的速度测量。逻辑 KV 缓存随圈数增加。参数少本身不能推出更省推理时间。

除固定 K、固定生成上限的机制对照，再做同推理预算对照：以两圈或四圈实测的总 GPU 时间为预算，给单圈 SFT 相近时间做多次独立采样并多数投票；预先在开发集标定采样次数、温度和平票规则。按整个评测集的总秒数和 GPU 数对齐、报告剩余差距；差距较大时画“准确率–GPU 秒”曲线。单圈和多圈都算 prompt 处理、解码和多样本成本。等输出 token 数单独列示。

**与 TaH 系列的关系。** TaH 有选择性迭代与 depth-aware LoRA；TaH2 联合训练 backbone、updater 和 decider。它们是相关系统参照。正式阶段可在 1.7B 上另表跑公开 TaH2 checkpoint，并在相同题目、可兼容的官方模板和相近实测预算下报告效果、训练数据差异及平均迭代数。由于训练数据和策略不同，不用公开 checkpoint 的分差归因于“旋转优于 TaH2”。同协议自建的 LoRA 和恒定旋转承担公平的机制比较。[TaH 论文](https://proceedings.mlr.press/v306/fu26t.html) · [TaH2 论文](https://arxiv.org/abs/2609.35748) · [官方仓库与权重入口](https://github.com/thu-nics/TaH)

## 6. 最后交付什么，什么时候下结论

建议后续实现按交付物验收：先有首圈等价、缓存和因果性报告；再有两圈五组逐题预测和纠错表；然后是四圈核心消融、三种子与计算成本；最后是 1.7B 复现、跨任务和外推曲线。每次运行留模型 revision、数据划分/样本 ID、种子、超参、GPU 型号、依赖版本，以及可复查的逐题预测。

| 观察到的最强结果 | 合适的结论 |
|---|---|
| 只有首圈对齐 | 工程上保留了原始单圈路径。 |
| 两圈优于无训练基线，但普通单圈 SFT 或断回接也能达到 | 少量旋转参数能适配任务，额外循环的价值仍待确认。 |
| 两圈净收益稳定；四圈时恒定旋转与按圈旋转持平 | 旋转可用作循环适配器，圈数乘方规则尚无独立优势。 |
| 按圈旋转稳定优于恒定旋转，使用上一圈状态有帮助，并在相同计算预算下有竞争力 | 这支撑 SpinLoop 的核心论文主张。 |
| 上述结果在 1.7B 和新任务复现，6 圈再胜同计算的封角对照 | 可以进一步主张可迁移，并在已验证的范围内有深度外推收益。 |
